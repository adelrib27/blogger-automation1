# Pedidos de blogs reais — V31

Cada arquivo `<site_key>.json` é criado **somente quando um blog real foi registrado** em `site_routes.json` ou `sites.d/`, com o assunto informado naquele momento. Não predefinir assuntos nem campanhas.

Contrato: `{"site_key":"blog_real", "platform":"blogger", "topic":"tema informado agora", "articles":6, "enabled":true}`. O site e sua campanha devem existir antes do pedido. **Nunca gravar chaves de API, emails, senha, URL afiliada ou IDs secretos neste arquivo.** `articles: null` habilita geração contínua, **sem limite total**, e mantém os limites por execução do gerador (Blogger até 1 rascunho/dia; WordPress até 1 por execução). Número inteiro de 1 a 24 continua válido quando o proprietário quer uma quota finita. O limite 24 na seleção R2 é tamanho de busca, não teto de artigos para pedidos contínuos.

Um pedido novo entra no fluxo diário de cache (até 3 mutações por dia no total), mas **não cria nem publica artigos**. Itens em revisão permanecem bloqueados para conversão. `enabled` controla exclusivamente a demanda editorial. `commercial_enabled` (opcional; na ausência herda `enabled`) controla a fila comercial regular. Para preparar cache sem criar artigos, use `enabled:false, commercial_enabled:true`; para suspender ambos, use false nos dois campos. Pilotos e recuperação editorial exata continuam exigindo `enabled:true`. Não usar flag comercial como autorização de DRAFT/LIVE. O máximo de 24 ofertas por busca R2 é apenas um lote de seleção. Para produção contínua, use `"articles": null`; a ausência de produto novo com imagem e link afiliado seguro deve encerrar sem criar rascunho, nunca forçar produto repetido.
